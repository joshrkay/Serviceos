# B7.5 — spoken parts with qty + unit: contract design (Fable-authored)

Money-adjacent surface. The contract change is build-blocking and lands FIRST, in its own
commit, **held for human review** per Guardrail 3 (it touches the money-bearing line-item
contract even though it moves no money).

## The invariant this must not break

`unit` is **descriptive only**. Price stays integer cents; `quantity × unitPriceCents =
totalCents` is untouched. No billing-engine arithmetic reads `unit`. Pinned by existing
billing-engine unit tests staying green plus one new assertion that a line carrying a `unit`
totals identically to the same line without one.

## Layers to change (in this order)

1. **DB** — new migration (next free number after `264_create_payment_refunds`; verify at write
   time, and NEVER edit an existing migration — the immutability test forbids it):
   `ALTER TABLE estimate_line_items ADD COLUMN IF NOT EXISTS unit TEXT;` and the same for
   `invoice_line_items`. Nullable, no CHECK constraint at the DB layer (the Zod enum is the
   validation boundary; a CHECK would make future catalog-unit additions a migration).
2. **Shared contract** — `packages/shared/src/contracts/money.ts`: add
   `unit: catalogUnitSchema.optional()` to `lineItemSchema`, where
   `catalogUnitSchema = z.enum(['each','hour','sq ft','per lb','per gal'])` mirrors
   `CatalogUnit` (`packages/api/src/catalog/catalog-item.ts:5`). Export the schema and its
   inferred type. Note in a comment that the enum is kept in lockstep with `CatalogUnit` — add
   the lockstep assertion to `money.test.ts` alongside the existing category lockstep check.
3. **Billing engine** — `packages/api/src/shared/billing-engine.ts`: `unit?: CatalogUnit` on
   `LineItem` (import the type or restate the union — prefer importing from shared to avoid a
   third copy). `buildLineItem` passes it through untouched.
4. **Estimate editor input** — `packages/api/src/estimates/estimate-editor.ts:30-44`
   `EstimateEditLineItemInput`: `unit?: CatalogUnit`. Thread to the persisted row.
5. **Row mappers / repos** — wherever estimate/invoice line rows are read and written, map
   `unit` both directions. Grep for `unitPriceCents` mapping sites; every one that persists or
   serializes a line needs the new column, or the field silently vanishes on round-trip (this is
   exactly the class of bug the run exists to kill — pin it with a round-trip assertion).
6. **Catalog resolver** — `packages/api/src/ai/resolution/catalog-resolver.ts:558` currently
   copies only price/ids from the matched catalog item. Add `unit: item.unit`. The uncatalogued
   confidence cap (`UNCATALOGUED_CONFIDENCE_CAP`) is untouched and re-pinned by an existing test.
7. **Classifier entities** — `ExtractedEntities` gains structured part mentions
   `parts?: Array<{ name: string; quantity: number; unit?: CatalogUnit }>`. The classifier
   prompt + launch fixtures per AC-3.
8. **UI** — unit renders on estimate review line items and the customer approval page; jsdom
   class-contract test + 320px Playwright viewport check (repo rule).

## Targeting rules (AC-4)

Named document → that document. "the job" / unnamed with exactly ONE open estimate-or-invoice on
the resolved job → that document. Multiple candidates → `voice_clarification` with candidates.
None → honest gate (`missingFields`), and **the draft preserves the structured parts** so nothing
spoken is lost. No auto-created estimate in this run (Part F entry F-4).
