# Comms Extraction Findings

Read-only discovery pass across the Rivet comms subsystem (`packages/api`,
`packages/shared`). Generated by `/comms-extract all` (four parallel
tracks). State only — `EXISTS` / `PARTIAL` / `ABSENT` with `file:line`;
no fixes proposed. Feeds the §8 migration plan, the harness spec, and the
(not-yet-written) `RIVET_GOAL_COMMS.md`.

## P0 — silent gaps (surfaced first, unconditionally)

Four P0s. One is the entitlement gap (Track 1); three are partial-deletion
paths (Track 3). The RLS audit came back **clean** — no cross-Account leak
was found, which is called out explicitly so downstream work does not
re-litigate an unaudited assumption.

**P0-1 — No entitlement layer exists; comms sends are gated nowhere by
entitlement.** (Track 1) Zero `entitlement` symbols in `packages/`. The
transactional comms path gates only on settings toggles, invoice-state
suppression (I10), and consent/DNC — never on whether a tenant is entitled
to a comms capability/quota, at read time or write time.
`packages/api/src/notifications/transactional-comms-service.ts:53-63,159,267,317-321,355`.
Greenfield: nothing to migrate, built from zero.

**P0-2 — Recording-retention purge deletes audio only and deliberately
retains the other three data classes.** (Track 3) The retention sweep
deletes the S3 audio object and tombstones `voice_recordings.purged_at`,
but by explicit design keeps transcripts, summaries, and derived data
(embeddings + commitments). After the audio is "purged," three of four
classes of the same recording remain.
`packages/api/src/workers/recording-retention-worker.ts:9-13,186-189`.

**P0-3 — Tenant deprovision deletes DB rows for all four classes but
orphans the S3 audio bytes.** (Track 3) `deprovision.ts` issues SQL
`DELETE` across every `tenant_id` table (reaching all four DB stores) but
makes **no** object-store delete call — the `files` rows go, the
underlying `.mp3` objects survive.
`packages/api/src/tenants/deprovision.ts:161-195` (absence of any
`deleteObject`).

**P0-4 — No single-subject deletion (DSR / "right to be forgotten")
handler exists at all.** (Track 3) Erasure is only achievable via
full-tenant destruction — which is itself incomplete per P0-3. No
per-subject or per-recording deletion path was found in routes or workers.

> Legal-exposure item elevated alongside the P0s (Track 3): the recording
> **disclosure fires after capture is armed** on both telephony transports
> — a two-party-consent exposure, not a style issue. Detailed under Track 3

**State:** Account **PARTIAL** · Contact **EXISTS** · Location **EXISTS** ·
Entitlement layer **ABSENT** (enforced nowhere).

- **Account — PARTIAL.** No `accounts` table. The account concept is
  overloaded onto `customers`: `account_type` (`residential|b2b|property_manager`)
  at `schema.ts:2905,4560` and a self-referencing `parent_account_id` at
  `schema.ts:4535-4537`. Domain mirror: `customers/customer.ts:93,100,222,736`.
- **Contact — EXISTS.** `customer_contacts` (`schema.ts:4620`, roles
  `primary|billing|site|other`), repo `customers/pg-contact.ts`, shared
  contract `packages/shared/src/contracts/customer.ts`.
- **Location — EXISTS.** `service_locations` (`schema.ts:337`), FK to
  `customers`, geocode + `is_primary`.
- **Entitlement layer — ABSENT.** No symbol in `packages/`. Adjacent but
  distinct primitives: `tenant_feature_flags` (`schema.ts:3990`),
  `pack_activations` (`schema.ts:950`), consent (`tenant_dnc_list` +
  `consent_events`). None is a plan/quota entitlement.

**Tenant scoping (I1) — CLEAN (no P0 leak).** Every comms-adjacent table
carries `tenant_id NOT NULL` + a `tenant_isolation` RLS policy, with
`FORCE ROW LEVEL SECURITY` (inline or via the bulk block at
`schema.ts:3236-3263`): conversations (`110`/`121-124`), messages
(`130`/`143-146`), voice_recordings (`152`/`166-169`), message_dispatches
(`1097`/`1113-1117`), notes (`931`/`943-947`), tenant_dnc_list
(`1265`/`1272-1275`), call_summaries (`1306`/`1314-1317`),
call_transcript_turns (`1535-1538`), customers (`308`/`329-333`),
customer_contacts (`4622`/`4639-4643`), service_locations
(`339`/`359-363`). Runtime connects as a non-owner role
(`db/rls-runtime-role.ts`, `db/tenant-transaction.ts`), so even
ENABLE-only tables are isolated for app traffic.

**Drift from spec.** The spec (`.rivet/RIVET_OPERATION_CONTRACTS.md:37-41`,
recurring at `:171,195,212,243,252,285,435`) and the **entire

collapses to `SELECT DISTINCT c.*`, dropping contact identity. Account
hierarchy (`parent_account_id`, `findByParentAccount`) is consumed by no
comms/resolution site.

**Flat call sites (all runtime `customer_ref` uses):**
`proposals/contracts.ts:497,506,536,538`; `routes/assistant.ts:488`;
`workers/voice-lookup-answer.ts:150,255`;

**Migration impact (§8):**

## Track 3 — Consent, retention, deletion

**State:** pre-capture disclosure **PARTIAL** (exists but fires after
capture arms) · 4-class storage **EXISTS** · deletion reach **PARTIAL**
(two purge paths, each misses classes — P0-2/P0-3, plus no DSR handler P0-4).

- **Recording disclosure — EXISTS, fires AFTER capture starts.** Logic is
  state-aware (two-party list, unknown-state fail-safe):
  `packages/shared/src/legal/recording-disclosure.ts:19,60`;
  skill `ai/skills/disclose-recording.ts:147,161`; invoked in bootstrap
  `telephony/twilio-adapter.ts:1124`. **Firing order is the exposure:**
  - Gather/Record path prepends `<Start><Record>` as the first verb
    (`twilio-adapter.ts:632-638`); the disclosure `<Say>` is appended later
    (`:640-652`, greeting `:1189-1197`). `<Start><Record>` is async — audio
    is armed before disclosure is spoken.
  - Media-streams path returns `<Connect><Stream>` immediately
    (`twilio-adapter.ts:989`, `buildStreamTwiML:1342`); disclosure runs
    later on the WS `start` frame
    (`media-streams/mediastream-adapter.ts:1084-1092`). In-code comment
    confirms the hazard (`:1112`).
  - Fail-open: if `initializeSession` throws, the call **keeps recording
    with no disclosure** — `DISCLOSURE_INIT_FAILED`, call explicitly not
    hung up (`mediastream-adapter.ts:1101-1125`).
- **Four-class storage — EXISTS.**
  - Audio → S3 `<tenant>/<callSid>.mp3` + `files` row + `voice_recordings`
    row (`telephony/recording-webhook.ts:87,289-327`;
    `voice/voice-service.ts:455-527`).
  - Transcripts → `voice_recordings.transcript` + per-turn
    `call_transcript_turns` (`voice/voice-service.ts:48`;
    `schema.ts:1519`; `voice/pg-call-transcript-turn.ts:70`).
  - Summaries → `call_summaries` (`ai/skills/summarize-session.ts:222`;
    `schema.ts:1304`).
  - Derived → embeddings in `knowledge_chunks` (pgvector)
    (`workers/transcript-ingestion-worker.ts:363`; `schema.ts:1654`);
    commitments in `proposal_executions` (`schema.ts:1541`).
- **Deletion reach — PARTIAL (P0-2, P0-3, P0-4 above).** Two paths only:
  Path A tenant deprovision (`tenants/deprovision.ts:106,169-184`) reaches
  all four DB stores but orphans S3 audio (P0-3); Path B retention sweep
  (`workers/recording-retention-worker.ts:162,186-189`) deletes audio only,
  retains the other three by design (P0-2). No single-subject handler (P0-4).

**Legal-exposure flags:**
- **Two-party-consent exposure:** disclosure fires after capture is armed on
  both transports; fail-open path records with no disclosure at all (cites
  above).
- **PCI-adjacent storage:** raw transcript text stored unscrubbed in
  `voice_recordings.transcript` and `call_transcript_turns.text`
  (`schema.ts:1525`) — a spoken card/CVV/SSN lands verbatim there and in
  the S3 audio bytes. `knowledge_chunks` stores **both** raw (`content =
  scrub.text`) and `content_scrubbed`, with only a `residualPii` flag; scrub
  is best-effort and a scrub-to-empty chunk is skipped, not blocked
  (`transcript-ingestion-worker.ts:342-346,368-376`; `schema.ts:1661-1663`).

## Open decisions (D14–D19) — which ones the code already answers

The task named D14–D19 as open; the extraction touches several. The
findings do not decide them, but flag where existing code sets a precedent
that narrows the decision:

- **Entitlement model (P0-1):** the code answers this only in the negative
  — there is **no** entitlement layer, so any D-item assuming one is
  greenfield, not a choice between existing mechanisms. Adjacent primitives
  (`tenant_feature_flags`, `pack_activations`) exist as precedent for
  boolean capability gating but not quota/plan entitlement.
- **Account/Contact/Location model:** partially settled by precedent, not
  open — Contact (`customer_contacts`) and Location (`service_locations`)
  are already distinct tables; Account is overloaded on `customers`. Any
  decision here is "reconcile the existing split," not "design from
  scratch."
- **Channel-resolution precedence (C3-adjacent):** the code does **not**
  settle it — four divergent partial implementations and no last-used rung
  mean the decision is still open, and any doc claiming a canonical chain
  is describing intent, not code.
- **Email as a first-class conversational channel:** effectively pre-decided
  against by current code — email is send-only with no inbound route and no
  threading. A D-item assuming email threading parity with SMS is
  greenfield.
- **Retention vs erasure semantics (P0-2/P0-3/P0-4):** the code encodes a
  specific (and incomplete) stance — retention purges audio while keeping
  derived data by design. Any "right to be forgotten" decision must
  reconcile with that deliberate retention, not assume a clean cascade.
