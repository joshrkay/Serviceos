# AI Service OS ("Rivet") — User-Facing UI Feature Inventory

Scope covered: `packages/web` (React operator SPA), `packages/mobile` (Expo/RN owner-operator app), public/customer surfaces served by `packages/api`. Read-only survey; nothing modified.

**Shell / navigation model (context for everything below).** `packages/web/src/components/layout/Shell.tsx` renders three mode-aware navs — `supervisor`, `tech`, `both` — chosen by `/api/me.current_mode`, with a three-way segmented Mode toggle. Nav items carry a `requires` RBAC permission (`estimates:view`, `invoices:view`, `settings:view`), so technicians never see money surfaces. Desktop = sidebar; mobile = bottom bar (6 items max). `Dispatch`, `Inbox`, and `Money` are deliberately kept **off** the sidebar (URL-reachable only; approvals reachable via the proposal badge on the logo). All routes are in `packages/web/src/routes.ts` and lazily code-split.

**Feature flags.** There is a real flag system (`packages/api/src/flags/feature-flags.ts`, `pg-tenant-feature-flags.ts`, admin API at `routes/feature-flags.ts` gated on platform-admin) but **no web UI route is gated by a named flag**. Gating in the operator app is by *role/permission* (`requires:`) and by *mode*, not by flags. The only client-side toggles are `localStorage` QA overrides via `lib/uiFlags.ts` (e.g. `serviceos.technicianId`).

## Notable gaps I noticed (UI a field-service product usually has that I could not find)

**Scheduling / field operations**
- **No map anywhere.** No Mapbox/Google Maps/Leaflet/`MapView` in web or mobile. The dispatch board is technician *lanes* only; technician location is captured (GPS samples, arrival radius, presence) but never plotted. Mobile only deep-links out to the OS Maps app (`buildMapsUrl`). No route optimization, no drive-time visualization, no geofencing UI. (PRD does list route optimization/geofencing as out of scope for V1, but a dispatcher board without a map is unusual for the category.)
- **No month/week calendar grid.** `/schedule` is a rolling 7-day chip strip + day agenda; there is no month view, no multi-week view, no per-technician calendar column view.
- **No recurring-appointment / route-based visit series editor** beyond the per-customer `RecurringJobsPanel` and thin `/contracts`.
- **No on-my-way / arrival-window notification composer** for the operator (the tech-side auto-detect exists, but there's no operator UI to configure or manually send an "on the way" text with ETA).
- **No crew/capacity or availability calendar** (time-off, PTO, shift patterns). Business hours exist (`OperatorHoursSheet`), per-tech availability does not.

**Money**
- **No customer-side partial payment.** `/pay/:id` pays the full balance; partial is operator-entry only.
- **No refunds, credit notes, or voiding UI.** No "void invoice", "issue refund", or credit-memo surface in web or mobile.
- **No tax rate configuration UI** (line items carry `taxable`, invoices carry `taxCents`, but there is no settings sheet to define tax rates/jurisdictions).
- **No A/R aging report or statements.** Money dashboard gives one month of revenue/outstanding/overdue; there is no 30/60/90 aging table, no customer statement, and no dunning-schedule editor (reminders are a single "Send reminder" button plus an automation toggle).
- **No purchase orders / supplier ordering** — `SuppliersSheet` is a "find parts" lookup, not ordering.
- **No inventory / parts stock UI** (PRD: out of scope).
- **No payroll/timesheet approval view** — time entries are captured per job; there is no roll-up-by-technician-by-week approval screen.

**Notifications & comms**
- **No web push.** `public/sw.js` implements caching only — there is no `push`/`notificationclick` handler, and no `pushManager`/`Notification.requestPermission` anywhere in `packages/web`. Push is native-mobile only (expo-notifications).
- **No notification-preferences UI on web.** `GET/PUT /api/notification-preferences` exists and mobile has `NotificationPreferences.tsx`, but there is **no web Settings row** for it — a web-only operator cannot manage notification categories.
- **No email/SMS template editor for customer messaging** beyond estimate templates' `defaultCustomerMessage` (line-item structure is explicitly read-only, with the structural editor "behind a separate flow we haven't built yet").

**Customer-facing**
- **No portal login/authentication** — portal access is a 30-day bearer token in the URL, minted and sent by the operator. No customer self-signup, no password/magic-link re-entry if the link expires.
- **No customer-facing document downloads** (PDF estimate/invoice) from the portal — payment receipts come from Stripe email.
- **No e-signature outside estimate approval** — no signed job completion / work-authorization capture on the technician side, no signature on job forms.

**Platform / cross-cutting**
- **No feature-flag admin UI.** Flags are API-only, platform-admin gated; there is no operator or internal-admin screen.
- **No internal admin/tenant-management console in the web app** despite `routes/admin-tenants.ts` existing on the API.
- **No true i18n framework.** No `i18n`/`useTranslation` library anywhere — "Spanish language mode" configures *AI voice and customer messages*; the operator UI strings are hardcoded English.
- **Accessibility is partial**: `role="dialog"`/`aria-modal` on `ui/modal.tsx` and `ui/sheet.tsx` and most settings sheets, `aria-live` on error boundaries and voice status, roving-focus tabs, `prefers-reduced-motion` honored in `index.css`, ~241 `aria-label`s. But I found **no skip-to-content link, no focus-trap implementation in the modal/sheet primitives, and no documented contrast/axe audit** — the mobile invariants (44px, 320px) are the only pinned UI-quality tests.
- **No global search / command palette** across entities.
- **No saved views / bulk actions** on the list pages (dispatch's "Approve all" and inbox batch-approve are the only bulk affordances).
- **No in-app help center, support chat, or error-report UI** for the operator (there is an internal `lib/errorReporter.ts`).
- **Equipment/asset history** — the PRD promises HVAC equipment history; I found no equipment entity UI (only `CustomerRecordsPanel` for generic records).
