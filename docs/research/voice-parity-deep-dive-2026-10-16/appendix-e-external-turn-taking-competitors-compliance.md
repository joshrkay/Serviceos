## 1. Turn-taking and latency engineering (2026)

### 1.1 End-of-turn (EOT) detection: who does what

**Where the field has landed:** every serious stack layers a semantic/prosodic completeness model after a short VAD stop (200–300 ms) and makes the *wait* a function of model confidence. Your fixed 600 ms `endpointing` has no confidence term — it cuts off slow number-readers and waits too long after an obvious "yes".

### 1.2 Speculative / parallel execution on interims
- **LiveKit `preemptive_generation`** (enabled by default under `turn_handling`): starts the LLM on a `PREFLIGHT_TRANSCRIPT` (high-confidence-but-not-final STT event) and discards if the final differs; optional `preemptive_tts`. Cost = wasted tokens. https://docs.livekit.io/agents/logic/sessions/, https://docs.livekit.io/reference/agents-js/enums/agents.stt.SpeechEventType.html
- **Deepgram Flux eager EOT**: same pattern via `EagerEndOfTurn`→prefill, `TurnResumed`→cancel; lower `eager_eot_threshold` = earlier but more cancelled calls. https://developers.deepgram.com/docs/flux/configuration
- **Practice**: gate on partial stability, revise if final ≠ partial. https://elevenlabs.io/blog/voice-agent-latency-optimization
- **For your FSM + intent classifier**: classify on the eager/preflight transcript, pre-render the next node's TTS, commit only on `EndOfTurn`; cancel cost is a discarded TTS request.

### 1.3 Fillers and backchannels
- Retell: `enable_backchannel` + `backchannel_words` (voice-dependent, "experiment first"). https://docs.retellai.com/api-references/create-agent
- Vapi: `acknowledgementPhrases` (do not count as interruption) vs `interruptionPhrases` (always interrupt). https://docs.vapi.ai/customization/voice-pipeline-configuration
- Practitioner pattern: 3–4 pre-rendered neutral clips played the instant EOT fires, no LLM; fillers help most when waits exceed ~4 s and hurt when the answer is already ready; Full-Duplex-Bench-v3 found Ultravox's fillers overlapped user speech ~48 % of tool turns. https://dev.to/kenimo49/your-voice-agent-is-slow-here-are-5-tricks-to-hide-it-3pcb, https://arxiv.org/pdf/2604.04847
- Krisp Interrupt Prediction and LiveKit adaptive mode classify "mhm" (continue) vs "no, wait" (yield). https://docs.livekit.io/agents/logic/turns/tuning/

### 1.4 Barge-in thresholds and resumption

| Platform | Barge-in gate | Resume after false/short interruption |
|---|---|---|
| Vapi `stopSpeakingPlan` | `numWords` 0–10 (default 0 = VAD-based), `voiceSeconds` 0–0.5 (default 0.2), `backoffSeconds` 0–10 (default 1.0 blocks agent audio after interruption). Community tuning: numWords 2, voiceSeconds 0.5, backoff 0.6–1. | No resume; new turn. Recovery example 1.0 backoff + 1.8 processing + 0.4 wait = 3.2 s. |
| LiveKit | 0.5 s speech and/or N words; adaptive model | `false_interruption_timeout` 2 s then **resume from where it stopped** (default). |
| Twilio CR | `interruptSensitivity` high/med/low; `interruptible` | You receive `utteranceUntilInterrupt`; truncate history yourself. |

### 1.6 Recommended budget for your stack (Twilio Media Streams 8 kHz μ-law → Deepgram → FSM+intent LLM → ElevenLabs)

| Stage | Target p50 | Target p95 | Levers |
|---|---|---|---|
| PSTN + Twilio ingress → your WS | 60–100 ms | 160 ms | Same-region server; measure with Voice Insights RTP latency |
| Deepgram interim→EOT decision | 250–400 ms (vs 600 ms fixed today) | 700 ms | Move to Flux (`eot_threshold` 0.7, `eager_eot_threshold` ~0.5, `eot_timeout_ms` 1500–2500, mulaw/8000) or keep Nova-3 with `endpointing=300` + `utterance_end_ms=1000` + confidence-aware wait |
| Intent LLM (small model, classify only) | 150–300 ms | 500 ms | Run speculatively on EagerEndOfTurn/interim; prompt-cache; cap output tokens |
| FSM transition + TTS request | <20 ms | 50 ms | Pre-render static node prompts as cached μ-law |
| ElevenLabs Flash v2.5 TTFB (WS, `ulaw_8000`, `auto_mode` for full sentences) | 150–250 ms | 400 ms | Keep WS warm; send first sentence early; `flush` |
| Egress to caller | 60–100 ms | 160 ms | 20 ms frames, no extra jitter buffer |
| **Total caller-perceived (quiet → first audio)** | **~700–900 ms** | **≤1.5 s** | Matches "natural" guidance (P50 <800 ms, P95 <1.5 s) and beats every platform on OpenBenchmarks |
| Barge-in stop | ≤150 ms from caller speech start to TTS stop | 300 ms | VAD-start + clear Twilio buffer (`clear` message); require ≥2 words or ≥0.4 s for *acting* on it; resume if no transcript within 2 s |

Why: eot-bench shows ~550 ms EOT delay at 5 % false-cutoff with a learned detector vs 1.6 s for pure VAD; the market's caller-side p50 is 1.3–1.7 s, so 0.8 s is a clear win. 800/1500 guidance: https://hamming.ai/resources/how-to-evaluate-voice-agents-2026

## 2. Bland.ai mechanics

**Node types** (tutorial lists 6; API lists more): Default (prompt or static text; a *condition* must be met before leaving the node), Webhook, Knowledge Base, End Call, Transfer Call (`transferNumber`), Wait for Response, SMS, Custom Code, Press Button, Transfer Pathway, Scheduling; 2026 additions: Code nodes, Custom Tool nodes (attach a library tool, live vs staging, "After Tool Response" routing, inputs bound from previously extracted pathway variables), Tool Chains. https://docs.bland.ai/tutorials/pathways, https://docs.bland.ai/api-v1/post/update_pathways, https://docs.bland.ai/changelog/04_06_2026

**Global nodes**: a node implicitly connected to every other node via a "Global Pathway Label"; global nodes take precedence over the agent's normal condition decisions; "auto return" (default on) sends the dialogue back to the triggering node after the global node fires; toggle off to wire explicit exits; a global node can be set to redirect instead of generating dialogue. Common uses: "transfer to live agent", "hours question mid-booking". Global *prompt* ("Add Global Prompt to All Nodes") is separate — personality/tone instructions appended to every node. https://docs.bland.ai/tutorials/pathways, https://university.bland.ai/modules/3/lesson-1

**Knowledge Base node / retrieval**: pathway KB node = text pasted into the node's "Knowledge Base" field that the agent searches (PDF/vector integration listed as "coming soon" in that tutorial). Account-level vector KBs (`/v1/knowledgebases`, returns `vector_id`, passed to agent tools; the `description` is read by the model to decide when to search) are marked **deprecated** in the API reference. No documented chunk/top-k limits found. https://docs.bland.ai/api-v1/post/vectors, https://docs.bland.ai/tutorials/pathways

**Webhook node / tools**: since 2026-03 webhook tools attach inline to a Default node with URL, auth, headers, body, "speech during execution", timeout + retry limits, and response-variable extraction (JSON path → `{{var}}`). Legacy Custom Tools use JSON payload with agent-extracted variables. https://docs.bland.ai/changelog/03_23_2026, https://docs.bland.ai/tutorials/tools

**Variables & dynamic data**: `request_data` key/values on Send Call are templated as `{{var}}` in prompts; `dynamic_data` is an array of pre-call HTTP requests (`url`, `method`, `headers`, `response_data[]` naming variables to extract) that can chain (`{{prev_call_id}}` in later URLs); pathway variables declared as `[name, type, description]` triples and extracted per node; call logs show which node set each variable. https://docs.bland.ai/tutorials/dynamic-data, https://docs.bland.ai/api-v1/post/calls, https://docs.bland.ai/api-v1/post/update_pathways

**Post-call analysis**: (a) `summary_prompt` on Send Call / inbound number for the auto summary; (b) `POST /v1/calls/{id}/analyze` with `goal` + `questions: [[question, type]]`; (c) `analysis_schema` still validated by the API (third-party 400s) but no longer a documented page; (d) Enterprise-only **Citation schemas** (`citation_schema_ids`) extract typed variables tied to specific utterances, delivered in the post-call webhook `citations[]` 30–60 s after hangup; webhook payload also echoes `metadata`, `transcripts`, `concatenated_transcript`, `answered_by` (AMD result), `recording_url`. https://docs.bland.ai/api-v1/post/calls-id-analyze, https://docs.bland.ai/enterprise-features/citations, https://docs.bland.ai/tutorials/post-call-webhooks, https://docs.bland.ai/api-v1/post/inbound-number-update

**Testing**: web chat (text/voice), real call, per-node unit test (choose start node, draft vs published). **Testbed**: pick a logged call, isolate one node, edit prompt, rerun to see variance, then "publish as a Standard". **Standards**: node-level regression — a prompt vs a *scenario* run **10×**, each run judged against success criteria, tallied against an overall threshold; scenarios are generated from a source conversation as a simulation prompt or permutations. **Scenarios / Evals** exist in the docs index (Evals = post-call grading with per-dimension judges, pass/fail to 5-tier verdicts, weights 0–100 per third-party **[UNVERIFIED]**; "Outcomes" Enterprise-only). https://docs.bland.ai/tutorials/testbed, https://docs.bland.ai/tutorials/standards, https://www.cekura.ai/discover/test-bland-ai-voice-agents

**Versioning**: pathways have a draft + numbered versions; *publish* snapshots draft → new version → **production** (live calls switch immediately); a version can be promoted to **staging**; calls can pin `pathway_version`. API: `POST /v1/pathway/{id}/version`, `GET …/version/{vid}`; CLI `bland pathway versions|promote`. Personas have "Promote to Production"/"Reset Draft". https://docs.bland.ai/api-v1/post/create_pathway_version, https://docs.bland.ai/sdks/cli, https://docs.bland.ai/tutorials/personas

**Pricing pass-through** (Dec 2025): Start $0 / **$0.14 per connected min**, Build $299/mo → $0.12, Scale $499/mo → $0.11; transfer time $0.05/0.04/0.03 per min on Bland numbers (free with BYO Twilio); outbound attempt minimum **$0.015**; telephony billed separately at unpublished pass-through (est. $0.01–0.02/min) — homepage and pricing page conflict **[UNVERIFIED]**. https://zeeg.me/en/blog/post/bland-ai-pricing, https://www.happyrobot.ai/hub/bland-ai-reviews-and-pricing, https://www.layer3labs.io/guides/bland-ai-pricing

## 3. Avoca and SMB-turnkey comparables

### 3.1 Avoca (ServiceTitan/FieldRoutes-centric, $1k–3.5k/mo custom-quoted, 2-week to 4–12-week onboarding — all third-party estimates)

Call forwarding modes: primary, after-hours, overflow. https://help.avoca.ai/llms.txt, https://help.avoca.ai/calls/review-calls
